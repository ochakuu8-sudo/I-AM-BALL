# Rolling Town — 坂道の街

Blenderで作った住宅街をボールで走り、体当たりで壊せる、PC・スマートフォン向けのThree.js試作です。
公開URL: https://ochakuu8-sudo.github.io/I-AM-BALL/

リポジトリ: https://github.com/ochakuu8-sudo/I-AM-BALL

## 操作

| 操作 | PC | スマートフォン |
| --- | --- | --- |
| 移動 | WASD / 方向キー | 左のスティック |
| ジャンプ | Space | JUMP |
| ブレーキ | Shiftを押し続ける | BRAKEを押し続ける |
| カメラを回転 | 画面をドラッグ | スティック・ボタン以外の画面をスライド |
| カメラを正面に戻す | C / 右上の照準アイコン | 右上の照準アイコン |
| スタート地点に戻る | R / 右上のリセット | 右上のリセット |
| 一時停止 | P / 右上の一時停止 | 右上の一時停止 |

移動はカメラ基準です。カメラを回しても、スティックを上へ倒すと画面の奥へ進みます。左指で移動しながら、別の指で視点を動かせます。上下の視点角度には制限があり、建物や地形が遮るとカメラをボール側へ即座に寄せます。遮るものがなくなるとゆっくり元の距離に戻ります。建物の透明化は行わず、飛び散る破片はカメラを押し動かしません。画面から離れると自動で一時停止します。縦・横画面に対応しています。
音は初期状態でオフ。音ボタンでジャンプ音・破壊音を有効にできます。

勢いをつけて壁、木箱、車、木、街灯、植栽などにぶつかると壊れます。木箱は弱く押すと転がり、強くぶつかると板に割れます。家は壁・床・屋根・ベランダ・基礎に分割してあり、壁を抜いた部分から通り抜けられます。1階の壁を35%以上失うと残りも崩れます。リセットで街全体が元に戻ります。

## 試作の構成

- **TypeScript + Three.js**: 街・ボール・追従カメラを描画。
- **Rapier**: 球、坂、家、車、ジャンプ台、動く木箱・コーンの当たり判定。1/60秒固定更新と描画補間。
- **React + Vite**: 画面上の操作パネルと静的ビルド・プレビュー環境。ゲーム本体はクライアントで動作し、ゲーム用バックエンドは不要。
- 配布時は`dist/client`へHTML・JavaScript・GLBを静的出力します。Three.jsと物理処理は`lib/town`に独立させています。
- **Blender 5.2**: 屋根・窓枠・玄関・バルコニー・雨どいなどをモデリング。家の3色の派生から14棟の街区を構成。

球には慣性を残しつつ、加速・旋回を補助しています。視点は球の回転から独立し、ドラッグ操作で360度回せます。移動・視点・ブレーキはそれぞれ指のIDを保持し、指を離す・キャンセル・一時停止の際に入力を解除します。
破壊はRapierの接触力から衝撃量を判定し、固定パーツを動的な破片へ切り替えます。家の装飾は近くの壁や屋根に含め、当たり判定はパーツごとの簡略化した箱です。道路・地形・ジャンプ台は固定です。コーンは押して動かせます。

破片は同時に最大80個、7秒で消えます。古い破片は見た目と当たり判定を一緒に消し、リセット時には元の位置と固定状態に戻します。破片同士の衝突は省き、地面とボールには衝突します。Blenderで色を頂点に焼き込み、繰り返しの形はThree.jsのInstancedMeshでまとめています。

破壊して飛び散る動きを優先し、全端末で影・3Dオブジェクトの半透明化・UIの背景ぼかしを省いています。半透明用の複製メッシュは生成せず、破片の表示更新も不透明メッシュだけに行います。ボールの丸い影も描画しません。面ごとの照明による立体感と鮮やかな色は維持しています。

配色は黄・青・コーラルの家、青や赤の屋根、鮮やかな植栽で構成しています。道路は彩度を抑え、赤と白のボールが見つけやすいようにしています。Blenderの色指定はsRGBからリニア値へ変換して書き出し、ブラウザでは白飛びと過度な霧を抑えています。モデルの内容から読み込みURLのバージョンを生成し、更新後に古い色のモデルがキャッシュから残りにくくしています。

## 起動と確認

Node.js 22.13以降とnpmを使用します。

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

表示されたlocalhost URLを開きます。同じLANのスマートフォンではPCのLAN IPアドレスと同じポートを使用します。

```sh
npm run test:physics
npm run test:controls
npm run test:assets
npm run lint:game
npx tsc --noEmit
npm run build
```

`scripts/test-physics.mjs`は、坂の接地・加速旋回ブレーキ・ジャンプ・入力の先行受付・家の部分破壊・木箱の移動と破壊・家の崩壊・破片数と寿命・ジャンプ台・リセット・描画頻度の違いを13シナリオで確認します。数値結果は`art/physics-report.json`に保存されます。
`scripts/test-controls.mjs`は4方向のカメラに対する移動を実際の物理で検証し、指の取り違え・キャンセル・上下角の制限・視点リセットを確認します。壁の手前への即時移動、破壊後の復帰、飛び散る破片の除外、異なる描画頻度でのカメラ復帰も検証します。`scripts/test-assets.mjs`はすべての破壊パーツについて、GLBの位置・回転・大きさと当たり判定が一致すること、色とメッシュ共有が保たれていることを検証します。
ブラウザのWebMCP対応環境では、状態取得・一時停止/再開・リセットも利用できます。未対応環境でもゲームは動作します。

## GitHub Pagesへの公開

`main`にpushすると、GitHub Actionsが型検査・ゲーム部分のlint・物理・操作・アセットのテスト・静的ビルドを実行し、成功した出力だけをGitHub Pagesに公開します。手動実行はActionsの「Deploy GitHub Pages」から行えます。

ワークフローは`.github/workflows/pages.yml`です。配信ファイルは`dist/client`、ビルド時の`PAGES_BASE_PATH`は`/I-AM-BALL`です。ローカル開発ではこの環境変数を指定せず、ルートURLから動作します。

GitHubリポジトリのSettings → Pages → Build and deploymentは「GitHub Actions」を使用します。追加のサービス用APIキーは不要です。

## Blenderとアセット

| ファイル | 内容 |
| --- | --- |
| `art/hillside-house.blend` | 編集できる家のBlenderシーン |
| `art/rolling-town.blend` | 街全体のBlenderシーン |
| `art/hillside-house.png` | 家のBlenderレンダリング |
| `art/town-overview.png` | 街全体のBlenderレンダリング |
| `art/build_town.py` | 家・街・小物を生成し、GLBを出力するスクリプト |
| `art/destruction.py` | 壁・屋根などの分割、頂点カラーと物理配置の出力 |
| `public/models/town.glb` | 地形の固定メッシュと1,000個以上の独立した破壊パーツ |
| `public/models/house.glb` | 家単体のモデル |
| `public/models/colliders.json` | 地形・建物・車・小物の物理配置 |
| `lib/town/simulation.ts` | 物理、加速、旋回、ジャンプの調整値 |
| `lib/town/game.ts` | Three.js描画とカメラ |
| `lib/town/controls.ts` | カメラのドラッグ入力と視点基準の移動方向 |
| `lib/town/camera.ts` | 壁・地形の手前へのカメラ移動と距離の復帰 |

```sh
blender --background --factory-startup --python art/build_town.py
```

Blender実行ファイルがPATHにない場合は、その絶対パスを指定します。実行すると上記モデル・Blenderシーン・確認用画像を再生成します。
家の画像はBlenderのレンダリングであり、ブラウザ画面のスクリーンショットではありません。
